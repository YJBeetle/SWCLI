## Revised external-host gate

Commit `bdc511a` replaces direct EXE launch with an independent Python COM
fixture. The fixture has no SWCLI import or daemon connection, enables native
foreground lifetime, waits for startup completion and exits. The gate then
requires the exact visible SW process to remain alive before daemon attach, and
retains stop-preservation/reattach/external-disconnect/no-silent-restart checks.
No registry flags or consent dialogs are changed. This verifies external host
ownership without claiming to test first-use double-click startup.

The portable suite now has 262 passing tests, including fixture startup failure
cleanup and refusal to reuse an existing host or reinterpret an access failure
as a missing host. Local VM and hosted results for the revised gate must be
recorded separately; the earlier direct-EXE CI failure is not relabeled green.

After the user's VM reboot, the final installed-wheel run of the complete native
smoke passed with `bdc511a` plus wrapper fix `b2654d0`, including both owned and
external-host lifecycles and the CP936/Unicode plate example. The external
fixture reported native startup complete, `visible: true` and
`user_control: true`; its Python process exited before attachment, and daemon
stop preserved that same visible SW PID. Reattach, external termination,
truthful disconnect, blocked business requests and graceful stop all passed.
The final cleanup left no fixture SW process, and the pre-existing Marketplace
startup value remained `DWORD 1` without any registry writes by this fixture.

The first wrapper revision rejected a real VM host despite its complete
`host-acquired`/`ready` output and empty stderr. Capturing the process handle
immediately after `Start-Process` made exit-code retrieval reliable in Windows
PowerShell, including a short-lived venv launcher. The targeted attach/stop
probe and subsequent complete native smoke both passed after this fix.

[SWCLI run 37563943890](https://github.com/YJBeetle/SWCLI/actions/runs/37563943890)

## Not established by this evidence

Driving dimensions, full constraint solving, topology-stable references,
transactions/rollback, remote authentication/file transfer, SDK/MCP and an
OpenSCAD converter are not implemented by these checks. A transient `HostBusy`
pre-operation rejection is covered by deterministic worker tests; this record
does not claim every GUI-busy condition was reproduced on the real host.
