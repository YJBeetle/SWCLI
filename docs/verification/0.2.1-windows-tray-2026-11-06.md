## Preserved first failure

The original `a47b89c` native test immediately required
`Shell_NotifyIconGetRect == S_OK`. Its preserved failure returned HRESULT 1.
A single registered diagnostic icon also returned 1 during five seconds of
read-only observation. Opening the overflow area subsequently made a registered
icon's rectangle available; the actual daemon icon was also visually observed
in the main notification area. Location/placement must not be confused with
registration. Microsoft's documentation states that Windows normally places
new icons in overflow and the user chooses whether to promote them:
[notification-area guidance](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area#add-a-notification-icon).
The native gate now verifies registration/removal directly without changing
user placement settings or converting an unavailable desktop into a pass.

Earlier diagnostic setup, DPI-coordinate, synthetic callback and overflow-only
lookup failures remain in the evidence directory. They are not counted as
successful UI acceptance. In particular, a nonzero location result is not
given an undocumented universal meaning.
