## Native binding lesson

Checking the truthiness of `SetUserPreferenceToggle` falsely rejected a working
native setter, because this late-bound host returns `None`. The adapter verifies
the actual preference via `GetUserPreferenceToggle`, both after suppression and
after restoration. A regression test covers the successful void-return setter;
other tests require failure/warnings when the actual state is wrong. No consent
dialog was accepted and no licensing registry flag was modified.

## Typed operations and installed Windows wheel

The development branch now exposes `sketch.dimension-diameter`,
`dimension.inspect` and `dimension.set` through the one daemon-backed protocol.
Creation/set obey lease/update-stamp/document/session guards; inspect does not
activate, select, rebuild or enter an edit. A short `m-xxxxxx` retains the exact
native dimension and its owning registered sketch, even after a partial failed
creation. Close/reopen or worker replacement invalidates handles. Native document
identity distinguishes external same-path reopening from wrapper replacement;
known disconnected proxies expire, while busy/unknown comparison errors fail
closed. Foreground restoration is verified without losing mutation evidence.

The portable suite reached **345 passing tests** after protocol, registry,
adapter, Schema and gate additions. This includes exact ownership, equation and
design-table refusal, driven/read-only state, failure/false-success evidence,
stale IDs, guarded background writes and restoration failure coverage.

An isolated Windows environment installed the built `0.1.0a5.dev0` wheel, without
`PYTHONPATH` or an editable source override. The gate invoked the installed CLI
for front-plane create/inspect/set and the same public protocol on top/right.
All three planes passed:

- diameter 16 mm -> extrusion 10 mm -> absorbed diameter edit to 20 mm;
- native radius/center, volume 2010.619298297468 -> 3141.5926535897966 mm³ and
  final area 1256.6370614359182 mm²;
- read-only stamps, cross-session lease/CAS refusal, duplicate refusal and exact
  foreground/session-current restoration;
- native save/reopen measurement and feature diagnosis, rejecting old sketch
  and dimension IDs after close/reopen.

Evidence and generated native models are retained in
`C:\Workspace\SWCLI-tests\a5-installed-driving-20261007` and
`C:\Workspace\SWCLI-tests\a5-installed-driving-final-20261007`. Each directory
includes the installed-wheel SHA256 record; these are development artifacts,

The final run additionally proved the real native indexed `Equation(index)`
getter: a test-only fixture added a diameter equation to an exact newly created
single-configuration part after checking the daemon PID and document identity.
Typed inspect reported its control, set returned `DimensionExternallyControlled`,
and diameter 16 mm, volume 2010.619298297468 mm³ and stamp **147** were unchanged.
Record: `a5-installed-driving-final-20261007\equation\equation-dimension-result.json`.
The fixture never activates a new COM host or touches preexisting documents.

Both gates are connected to the native Windows smoke workflow. DockerSW calls
the portable driving gate with its Linux CLI wrapper and explicit Wine-native
paths; evidence is separate from the six standard export outputs. The new Wine
run and new CI commit must pass before declaring delivery verified or cutting
a5. The scope/order is in [the a5 design](../design/driving-dimensions.md).

## CI findings and follow-up

The first typed driving CI runs did not pass and are not release evidence:

- SWCLI run `37585396069` passed packaging and Python 3.9/3.14 tests, but native
  Windows smoke failed before diameter creation. Requested circle center
  `(3, 4)` mm/radius 5 mm became native center `(0, 4)` mm/radius 8 mm.
  The API's UI inferencing/snapping path was not suppressed. Circle creation
  now temporarily enables/readbacks `AddToDB`, restores/readbacks the original
  mode, and retains the same final geometry verification. Unknown state or
  failed restoration is a failure, not permission to guess or retry.
- DockerSW run `37585548060` failed in the added driving gate's first circle
  with native `com_error` / `No access to memory location`, before it could
  return a feature. This is not established to share the Windows root cause.
  The artifact upload also failed because the root-created `mktemp` directory
  was mode 0700; DockerSW now makes this specific evidence directory readable
  by the host runner. The modeling failure must still be investigated using
  the next run's native stage/evidence, not hidden by a retry or skipped gate.

Read-only `sketch.list` now discovers exact 2D profile handles after native
reopen, including absorbed subfeatures. Its gate checks repeated-ID stability,
geometry, native stamp, foreground and both sessions' current state, without
reviving expired handles. Traversal indexes document-unique native `GetID`
values and verifies repeated native identity instead of doing all-pairs COM
comparisons. These changes require a fresh installed-wheel and Wine proof;
the earlier Windows directories above do not prove sketch discovery.
