# a5 internal adapter proof — 2026-10-07

The published release remains v0.1.0a4. This records unreleased native-adapter
progress, not a CLI/protocol/Wine capability claim.

## Verified first increment

- `create_circle_diameter_windows_with_handle` creates a current-configuration
  driving diameter on an exact, unabsorbed, single full-circle profile. It
  verifies native value and circle geometry after closing its own edit, refuses
  duplicate dimensions, and returns the precise native handle even when a
  later verification fails. It never promises rollback.
- Sixteen deterministic tests cover invalid/unrepresentable inputs, non-part,
  existing/stale/consumed/ambiguous profiles, selection/creation/set failures,
  driven/read-only refusal, false-success geometry/value, nonfinite result
  hygiene, failed preference suppression/restoration and owned-edit cleanup.
  The complete portable suite passed all 278 tests.
- The actual adapter was invoked from the current source on the user's Windows
  VM, with AMD64 Python 3.14.7, pywin32 312 and SW2025 SP5. This deliberately uses
  source for an internal probe: it is **not installed-wheel verification**.
  Front/top/right planes all created and verified 16 mm native driving diameter,
  rejected a duplicate, and left no sketch edit active. Native SW names and the
  Chinese configuration name were preserved in UTF-8 evidence.
- The independent probe then extruded 10 mm and changed that same dimension to
  20 mm through COM after absorption. Rebuild/measurement reported volume
  2010.619298297468 -> 3141.5926535897966 mm³ on all planes, unchanged centers and
  successful restoration of the original value-entry prompt preference.
  This proves feasibility of the next value-edit adapter, not that a public
  `dimension set` operation exists.
- Final evidence is retained at
  `C:\Workspace\SWCLI-tests\a5-driving-adapter-proof-v3\results.json` and its
  three generated native parts. Earlier probe directories remain available as
  failure evidence. All probe hosts exited; the VM remained running and its
  original idle-pause setting was restored. The global and venv a4 installation
  were not replaced by these source probes.

## Native binding lesson

Checking the truthiness of `SetUserPreferenceToggle` falsely rejected a working
native setter, because this late-bound host returns `None`. The adapter verifies
the actual preference via `GetUserPreferenceToggle`, both after suppression and
after restoration. A regression test covers the successful void-return setter;
other tests require failure/warnings when the actual state is wrong. No consent
dialog was accepted and no licensing registry flag was modified.

## Still required before public exposure

Dimension registry/liveness/ownership; request/result Schemas and catalog/CLI
integration; lease/update-stamp/session/foreground guards; read-only inspect and
verified value editing; installed-wheel Windows and real Wine gates. The
scope/order is in [the a5 design](../design/driving-dimensions.md).
