# SWCLI 0.2.2

- MCP `execute` returns a PNG preview for `document.render` and original CAD
  export bytes as embedded file resources for `document.export`. The adapter
  negotiates `include_content` through the live daemon schema; older daemons
  and explicit metadata-only mode retain their original behavior. The five
  MCP tool names and document/session/lease/CAS context stay unchanged.
- The daemon captures only its verified temporary output before publication,
  with an 8 MiB raw-byte limit and size/SHA-256 checks. The MCP client never
  reads a daemon host path. Original files and PNG previews have separate
  size/hash metadata. Attachment failures and oversized files remain distinct
  from successful CAD export; the successful operation is not repeated.
- Windows background startup uses the same Python installation's `pythonw.exe`
  for daemon and COM worker, retaining startup logs without a console window.
- The notification icon uses MacSW's purple cube artwork at native Windows
  sizes. Left-click has no action; right-click and select **查看状态** for runtime
  status. The `tasklist` status probe no longer opens a terminal window.
- Confirmed daemon stop and hide-icon retain their existing host/document
  protections. The status fix was checked in the Windows VM while preserving
  the same attached visible user SW.

The MCP extra includes Pillow for BMP-to-PNG presentation. Files beyond the
inline limit, general workspace transfer, and authenticated/encrypted remote
connections remain separate features. The version-tag workflow runs the
complete installed Windows gate and publishes the original same-run packages
only after success. DockerSW and MacSW releases remain independent.
