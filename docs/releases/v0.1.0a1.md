# SWCLI v0.1.0a1

This is the first public pre-release of SWCLI. It establishes a daemon-only,
typed automation boundary for SOLIDWORKS on native Windows and DockerSW/Wine
hosts without declaring the protocol stable yet.

## Included

- local `swclid` lifecycle with explicit owned or shared SOLIDWORKS hosting;
- versioned request, response, and capabilities schemas;
- short-lived document IDs and per-session current-document state;
- document open, list, inspect, status, diagnose, rebuild, save, close, render,
  and verified export operations;
- atomic render/export artifact publication and strict CI export validation;
- update-stamp preconditions and daemon-local document leases;
- deterministic box-part creation as the first typed modeling operation;
- Windows and DockerSW/Wine host diagnostics and packaging.

## Compatibility boundary

- `swcli/v1` is pre-stable and may change before `v0.1.0`.
- Document IDs and leases live only for the lifetime of one daemon worker.
- Leases coordinate clients of one daemon; they are not distributed locks or
  an authorization boundary.
- Remote transport has no authentication and must remain on loopback or behind
  a trusted tunnel.
- General sketches/features, stable entity references, operation batches,
  idempotent request replay, SDK, and MCP integration remain future work.
