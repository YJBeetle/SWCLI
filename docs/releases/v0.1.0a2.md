# SWCLI v0.1.0a2

This pre-release makes the typed protocol discoverable and safe to retry. It
keeps the daemon-only execution model introduced in `v0.1.0a1` while tightening
the contract used by automation and AI clients.

## Installation

On Windows, install the pinned wheel. The package installs pywin32
automatically:

```powershell
python -m pip install "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a2/swcli-0.1.0a2-py3-none-any.whl"
sw-cli version --json
```

For a portable Linux or macOS client that connects to an existing daemon:

```bash
python3 -m pip install "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a2/swcli-0.1.0a2-py3-none-any.whl"
sw-cli version --json
```

## Added

- per-operation JSON Schemas published by `sw-cli capabilities --json`;
- server-side request validation driven by the same operation catalog;
- caller-provided `--request-id` values for safe transport retries;
- bounded daemon-local replay of completed, semantically identical requests;
- explicit `RequestIdConflict` rejection when one ID is reused for a different
  operation or concurrency context;
- replay policy and replay status in capability and response envelopes;
- automatic pywin32 installation on Windows without an installation extra.

## Compatibility boundary

- `swcli/v1` remains pre-stable and may change before `v0.1.0`.
- Replay state is bounded, daemon-local, and lost on restart. It is not durable
  exactly-once execution.
- Request IDs identify semantic requests; changing the operation, parameters,
  session, document, update stamp, or lease requires a new ID.
- Remote transport still has no authentication and must remain on loopback or
  behind a trusted tunnel.
- General sketches/features, stable entity references, operation batches,
  transactions, SDK, and MCP integration remain future work.
