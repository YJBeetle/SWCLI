# SWCLI v0.1.0a9 — release candidate

This draft groups minimal assembly creation/insertion and native assembly/drawing
save-as, plus mesh exports. It is **not yet published**. The existing a8 release and its assets are
unchanged; formal a9 Windows/Wine and public-distribution receipts are pending.

## Changes since v0.1.0a8

- Discovery is concise by default: `daemon status` returns runtime state only;
  `capabilities` summarizes operation names and document-type `export_formats`.
  Use `capabilities --operation NAME --json` for one request/result schema pair,
  or `--full` for the full catalog. The new supervisor `daemon.capabilities`
  operation replaces querying the catalog through `daemon.health`. Upgrade
  client and daemon together; this pre-stable contract change has no legacy
  fallback. Export extensions are adapter support, not a translator probe.
- Windows bootstrap dependencies have at most three attempts with actual
  command/exit-code checks. This addresses Chocolatey's transient 503/false
  success; it does not retry CAD operations or hide final installation failure.
- `document export` adds STL, 3MF and AMF for parts/assemblies, and GLB for
  parts. Formats remain extension-selected; OBJ is not added. Both permissive
  and strict modes validate temporary output before replacing the target.
  Assembly STL scopes/restores single-file output, failing without publication
  if the host preference cannot be observed, enabled or restored.
- The generated native part/assembly gate strictly exports all four mesh
  formats in the same host session, checking artifact metadata, bounded file
  structure, unchanged source state and native source bytes. These eight
  modeling artifacts do not change DockerSW's existing six delivery exports.
- `document create --type assembly` creates an unsaved assembly from an actual
  `.ASMDOT` template. The returned exact document handle becomes only the calling
  session's current document. Failed creation can still return a registered
  document when SOLIDWORKS already created it; this is not rollback.
- `assembly add-component PATH` inserts one already-open, saved, clean `.SLDPRT`
  into a writable assembly. It supports an explicit source configuration and
  millimeter approximate-center inputs. Read-only/view-only targets, in-context
  component edits and unknown native states are refused. Native component
  identity, path/configuration and a one-component count increase are verified.
- `document save-as` now accepts `.SLDASM` and `.SLDDRW` in addition to `.SLDPRT`.
  The suffix must match the selected native document. Existing targets remain
  protected; use `document save` for in-place saving. The same live document ID
  and lease survive renaming, but closing/reopening creates fresh handles.
- The shared gate generates its own solid component and one-part assembly,
  verifies strict SaveAs/Save3 and writable/read-only reopening, and checks
  unchanged component bytes. Optional official drawings independently exercise
  in-place saving and strict renamed SaveAs with both reopen modes, fresh IDs,
  matching top-level trees, sizes and unchanged saved/source hashes.

## Example

On a matching daemon advertising these operations, with the saved clean source
part already available on the execution host:

```powershell
sw-cli --session assembly-demo document open 'C:\Workspace\component.SLDPRT' --read-only --json
$created = sw-cli --session assembly-demo document create --type assembly --json | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw 'assembly creation failed' }
$id = $created.document.document_id
sw-cli --session assembly-demo assembly add-component 'C:\Workspace\component.SLDPRT' --document $id --json
if ($LASTEXITCODE -ne 0) { throw 'component insertion failed' }
sw-cli --session assembly-demo document save-as 'C:\Workspace\new-assembly.SLDASM' --document $id --json
if ($LASTEXITCODE -ne 0) { throw 'assembly save-as failed' }
```

For an existing drawing, explicitly open it and use a new `.SLDDRW` target:

```powershell
sw-cli --session drawing-demo document open 'C:\Workspace\source.SLDDRW' --json
if ($LASTEXITCODE -ne 0) { throw 'drawing open failed' }
sw-cli --session drawing-demo document save-as 'C:\Workspace\new-drawing.SLDDRW' --json
if ($LASTEXITCODE -ne 0) { throw 'drawing save-as failed' }
```

These examples modify/rename live native documents and require authority to do
so. They do not save or package referenced models. Close/reopen and verify the
intended structure before treating output as an accepted deliverable.

## Boundaries

Mesh verification checks bounded containers and basic geometry, not complete
format conformance, watertightness, tessellation accuracy or material fidelity.
It does not add modeling operations or convert meshes back to native features.
Host translators and tessellation preferences remain prerequisites; STL carries
no unit declaration. Real Windows/Wine receipts for these additions are pending.

Native save-as is renaming, not SaveAsCopy, overwrite, detached-drawing conversion
or Pack and Go. It does not copy/request saving referenced models, and references
must remain accessible. Because the COM document adopts the target filename,
export's temporary-file-and-replace strategy is not applicable. A failed native
operation may leave a renamed or modified document; inspect its returned state.
Scalar SaveAs3 has no warning output: `save_warnings` remains `null`, not zero.
Minimum file size is a truncation guard, not a proprietary-format/geometry parser.

Assembly placement is a native approximate-center input, not an exact transform
or mate guarantee. No mates, nested/virtual components, stable component handles,
precise placement editing or assembly geometry measurement are added. Drawing
creation, sheet/view geometry and full reference semantics remain outside this
release. Top-level tree equality is not component-level geometry proof.

Generated assembly saves and drawing SaveAs have no modified-state exception.
An optional official assembly fixture may record `DocumentStillModified` during
its first preparation only, then requires strict in-place saving and clean
reopening; that test policy does not relax public CLI success conditions.

Request replay remains bounded, process-local, best-effort and nonpersistent.
The first terminal result, including failure, is replayed for a reused request
ID. A new attempt needs a new ID; daemon restart clears the cache. This is not
a transaction journal or automatic rollback.

DockerSW's shared Wine-Mono CCW runtime fix is a separate host change, not a
SWCLI wheel dependency or a native Windows fix. Host version pins and actual
runtime evidence must be reported separately. No MacSW deployment is performed
or claimed by preparing this release.

## Installation after publication

The following pinned URLs become usable only after publication. Until then use
the published a8 instructions or an explicitly selected development checkout.
Stop the old daemon before upgrading; handles, leases and replay memory expire.
Close owned-host documents before stopping. An attached daemon can detach
without closing the user's documents.

```powershell
python -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a9/swcli-0.1.0a9-py3-none-any.whl"
sw-cli version --json
sw-cli doctor --json
sw-cli daemon start --visible --json
```

Portable Linux/macOS client (Python 3.9+; paths remain execution-host paths):

```bash
python3 -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a9/swcli-0.1.0a9-py3-none-any.whl"
sw-cli --endpoint HOST:18495 capabilities --json
```

Windows installs pywin32 automatically. Installing a client does not install
SOLIDWORKS/Wine or transfer files. Keep unauthenticated transport inside a
trusted boundary. DockerSW/MacSW own their bundled installations and pins.
