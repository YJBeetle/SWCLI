# SWCLI v0.1.0a17

## 文档长度显示单位与精度

新增 `document units` 和 `document units-set`，读取文档长度显示设置，并在已校准的小数格式下修改毫米／英寸及 0～8 位小数精度。结果保留 GetUnits 的五个原生字段，未请求的字段保持原值。

写入沿用文档租约、会话和更新戳保护，同时提供 `--if-length-unit`、`--if-decimal-places` 检查预期旧值。原生 SetUnits 不推进已观察到的更新戳，因此单位值冲突需要这些旧值检查。相同值不调用 setter，成功改变后显式标记文档需要保存，原生失败保留可能已改变的状态。

本版是“选项 → 文档属性”的长度显示设置第一步。现有建模和测量协议继续采用毫米。整套单位系统、分数显示、其他物理量单位，以及注释字体、箭头和绘图标准在后续小步独立校准。

## Skills 来源与验收

用户要求的 skills 更新 `2d42a85`、`353a720` 已真实合并，新增摘要／配置属性指引及官方 COM API 导航随包保留。旧 API 指南的 `16075bd5c68f8f2898310a8b5763c6eb85972b87` 来源仍在祖先链中。

本地原生校准已验证零件、装配的单位／精度边界、旧值拒绝、几何保持和保存重开。安装后公共 CLI 的两类样件业务回执成功。首次本地外层脚本因过早检查 SW 退出而记录收尾失败，原报告保留；独立后续检查已确认进程退出，完整功能验收仍以 CI 原始回执为准。

首次完整 Windows CI 在单位门禁首次写入前失败：托管样件的十进制原生配置使用未启用的分数分母值 0，而本地样件为 8。已修正为兼容这两种已观察值并原样保留，仍拒绝分数显示及其他未验证配置。原失败证据保留，修正版的实际写入、保存重开和完整矩阵仍须 CI 验收。

此提交冻结精确版本 `0.1.0a17`，等待完整 Windows CI 和原始 wheel/sdist 资产核验。用户已授权在验收通过后择机合并发布；当前仍待完整 CI 与原始包核验。
