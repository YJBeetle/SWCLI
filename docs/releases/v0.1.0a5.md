# SWCLI v0.1.0a5

This pre-release adds the first native driving-dimension loop: create a circle
diameter, inspect/edit it after extrusion, save/reopen the part and discover a
fresh handle for the saved diameter. It is not arbitrary dimension support or
a stable `0.1.0` protocol release.

## Installation

Stop an old daemon before upgrading. Start the matching daemon explicitly after
installation; document/sketch/dimension IDs and leases do not survive a restart.

Windows (pywin32 is installed automatically; no `[windows]` extra):

```powershell
sw-cli daemon stop --json
python -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a5/swcli-0.1.0a5-py3-none-any.whl"
sw-cli version --json
sw-cli doctor --json
sw-cli daemon start --visible --json
```

Portable Linux/macOS client:

```bash
python3 -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a5/swcli-0.1.0a5-py3-none-any.whl"
sw-cli version --json
sw-cli --endpoint HOST:18495 capabilities --json
```

Python 3.9 or newer is required. The portable client does not install a
SOLIDWORKS/Wine host or upload local files. Remote use requires a trusted boundary
or authenticated tunnel, not an unauthenticated public daemon. DockerSW owns its
bundled client/daemon installation; do not install another copy in that image.

## Changes since v0.1.0a4

- `sketch dimension-diameter SKETCH_ID --diameter-mm VALUE` creates and verifies
  a real driving diameter on one exact, unabsorbed, full-circle sketch without
  existing dimensions. The circle center is preserved, not constrained.
- `dimension inspect DIMENSION_ID` reads exact native value, ownership and
  circle evidence. `dimension set DIMENSION_ID --value-mm VALUE` edits only the
  current configuration, including a sketch absorbed by a boss/cut. Native
  radius/value, rebuild diagnostics and downstream body metrics are verified.
  Driven/read-only, equation/design-table-controlled or ambiguous dimensions
  and existing sketch edits are refused rather than overridden.
- Read-only `sketch list` recovers fresh exact 2D sketch handles after opening
  or reopening a part, including absorbed profiles. Repeated observations reuse
  the same live ID; closed-document IDs never become valid again.
- Read-only `dimension discover-diameter SKETCH_ID` registers the observable
  unique current-configuration diameter of that single full-circle profile.
  It preserves foreground, session current, configuration, edit state and the
  update stamp. Empty/unavailable display chains, ambiguous dimensions and
  incomplete native observations fail without guessing names or forcing display.
- Document/session/lease/update-stamp guards, per-operation request/result
  Schemas and replay semantics cover the new operations. Native metadata and
  exact-object identity checks fail closed, including on background documents.
  Foreground restoration failures retain mutation evidence but cannot report
  success. The packaged agent usage guide documents the new public vocabulary.
- A failed native cut now ends its residual command via `SetPickMode()` before
  independent selection cleanup. This fixes the verified failed-cut -> close ->
  fresh part/sketch continuation fault on hidden Windows and Wine hosts without
  changing visibility, retrying the mutation or restarting the host. The original
  cut error remains; cleanup failures are warnings, not a rollback guarantee.
- Shared native gates cover Windows visible/hidden hosts and hidden DockerSW
  delivery. A real equation-controlled edit refusal remains mandatory in the
  visible Windows run; hidden mode does not bootstrap a second host through ROT.

## Minimal parameter-editing loop

With a matching running daemon, use the returned IDs rather than sketch names:

```powershell
sw-cli document create --json
$circle = sw-cli sketch circle --plane front --radius-mm 5 --json | ConvertFrom-Json
$diameter = sw-cli sketch dimension-diameter $circle.sketch.sketch_id --diameter-mm 16 --json | ConvertFrom-Json
sw-cli dimension inspect $diameter.dimension.dimension_id --json
sw-cli feature extrude $circle.sketch.sketch_id --depth-mm 10 --json
sw-cli dimension set $diameter.dimension.dimension_id --value-mm 20 --json
sw-cli document measure --json
```

Use fresh `sketch list` and `dimension discover-diameter` handles after native
save/close/reopen. A handle permits observation, not authority to modify/save
a user's source file. Check capabilities before using the operations.

## Boundaries and compatibility

- This remains pre-alpha. `swcli/v1` has no stable compatibility commitment;
  use matching client/daemon versions and advertised Schemas/capabilities.
- This dimension slice is one full-circle diameter in the current configuration.
  It does not add center anchoring, rectangle/linear/radius dimensions, arbitrary
  relations, multi-configuration edits or a full constraint solver.
- `d-`, `s-` and `m-` handles are document/worker-local, not persistent topology
  references. Close/reopen or worker replacement invalidates them. Native
  save-as keeps them only while that same document remains live.
- Failed native mutations may leave partial dimensions/features. Available
  handles/status are evidence, not automatic rollback. Diagnose/inspect before
  making a new attempt; verified geometry is not proof of engineering intent.
- Request replay is bounded, daemon-local, in-memory and best-effort. The same
  request ID returns the first terminal result, **including failure**. A new
  attempt needs a new ID; daemon restart clears the cache. It is not a durable
  transaction log. Leases/stamps do not lock GUI edits or other daemon instances.
- Host exit remains an explicit disconnected/recovery state, not a silent new
  SOLIDWORKS session. Native command cleanup is not a Wine source patch, and the
  slower visible Wine path is a separate limitation. No MacSW/macOS execution
  proof is claimed for this release.
- Authenticated remote transport/file transfer, stable topology references,
  batches/transactions, typed SDK/MCP, broader parameter/feature editing and
  assembly/drawing creation remain later work. OpenSCAD-to-editable-native
  modeling remains a longer-term application goal, not an implemented converter.
