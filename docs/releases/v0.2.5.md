# SWCLI 0.2.5

## Changes

- Manage additional document defaults for center marks, linear tolerances, Notes and general annotation fonts, drawing line fonts, dimension formatting, model display, tables, and image quality. Writes remain limited to the reviewed fields and value combinations for each document type.
- Read a nine-field unit profile and write the supported unit combinations with whole-profile compare-and-set. Drawing standards support the reviewed transitions between GB and other standards.
- Create a full-turn revolve from supported rectangular profiles. Use persistent face and edge references in supported single-body parts and get an explicit refusal when topology changes invalidate a reference.
- List and validate target faces on an active, saved, read-only assembly through the CLI, SDK and MCP. The reviewed scope covers the supported two-instance assembly and its component faces. Creating or editing mates remains outside this release.
- Export with the supported STL encoding, unit and tessellation options on isolated native Windows workers. Export STEP using AP203 or AP214 with the reviewed solid/surface and wireframe modes. STL and STEP restore temporary export preferences.
- Preserve partial mutation receipts when final bookkeeping fails. The transfer runtime computes large-file hashes without blocking other transfers, and failures retain the underlying transport phase and cause.
- Use `IModelDocExtension.SaveAs3`, `IConfigurationManager.ActiveConfiguration` and `IDimension.GetSystemValue3` on the native SOLIDWORKS paths.

## Compatibility

The native acceptance baseline is Windows SOLIDWORKS 2025 SP5. Assembly GLB export is checked against actual binary mesh data in a generated assembly. Standalone part GLB still uses the SOLIDWORKS exporter and rejects invalid output, including a missing or empty mesh buffer. GLB-specific tessellation controls and repacking external glTF buffers remain future work. DockerSW and MacSW have independent acceptance and delivery.
