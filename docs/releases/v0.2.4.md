# SWCLI 0.2.4

- Add `from swcli.sdk import Client`: synchronous typed methods for all 63
  current daemon operations, generated request/result TypedDict models, and
  packaged `py.typed` information for editors and type checkers.
- SDK methods reuse the existing daemon protocol and validate parameters,
  conditional requirements and document/session/lease/CAS context before IO.
  Optional omission stays distinct from false, zero, empty strings and null.
- `Response[T]` retains the original receipt, errors, partial state, request ID
  and replay information. `require_result()` explicitly raises for received
  refusals; transport errors preserve the phase and unknown-outcome flag.
- Per-client `TLSConfig` verifies certificates and hostnames without modifying
  process environment. `client.files.upload()` and `download()` reuse bounded
  workspace streaming, verification, explicit overwrite and explicit resume.
- Add schema-generation drift checks, strict Python 3.9-targeted type checking,
  positive consumer examples and eight negative typing cases to daily CI.
  Installed-package checks include the SDK typing marker and namespaces.
- Include a packaged SDK guide and update CLI/MCP agent skills to route Python
  workflows through the same native ownership and document protections.

The SDK supports Python 3.9+ without the optional MCP dependencies. Start the
daemon explicitly on its execution host before connecting. It does not own SW
lifetime, start/stop it implicitly, retry native operations, refresh CAS/leases,
select alternate entities, save or close documents automatically.

The version-tag workflow runs complete installed Windows verification before
publishing the original same-run packages. DockerSW and MacSW delivery cycles
remain independent.
