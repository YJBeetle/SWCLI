# SWCLI v0.1.0a3

This pre-release makes SOLIDWORKS startup and recovery explicit and improves
host lifecycle reporting on Windows and Wine.

## Installation

Windows (pywin32 is installed automatically):

```powershell
python -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a3/swcli-0.1.0a3-py3-none-any.whl"
sw-cli version --json
sw-cli doctor --json
sw-cli daemon start --json
```

Portable Linux or macOS client:

```bash
python3 -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a3/swcli-0.1.0a3-py3-none-any.whl"
sw-cli version --json
sw-cli --endpoint HOST:18495 capabilities --json
```

The portable client requires an existing daemon. Wine, SOLIDWORKS and Windows
Python are provided by the host integration, such as DockerSW.

## Changes since v0.1.0a2

- Typed commands require an explicitly started daemon. An unavailable local
  endpoint returns `DaemonUnavailable` with a startup hint.
- Idle workers detect external SOLIDWORKS exits on their owning COM thread.
  Status clears stale host information and reports `host_connected: false`
  with `HostDisconnected`; subsequent typed operations cannot silently create
  another SOLIDWORKS session.
- Temporary COM call rejection is tolerated; unknown probe failures must occur
  three times consecutively before the host is declared disconnected.
- `daemon stop` succeeds after host loss. `daemon restart` explicitly creates
  a new owned session. `--attach-existing` requires an existing host and returns
  `ExistingHostNotFound` when none is available.
- Slow-disk startup uses one COM activation and waits for that instance to
  become ready. Activation failures are reported without repeated activation
  or unreliable Wine ROT recovery. Wine class-factory registration wait is
  configured by the host runtime, not by re-launching SOLIDWORKS.
- Windows smoke tests cover external host termination, blocked operations,
  explicit restart and strict attach behavior.

## Upgrade and compatibility

Stop an old daemon before upgrading, then explicitly start the new daemon.
Document IDs and leases are temporary and are lost when its worker restarts.
Clients relying on implicit startup must add `sw-cli daemon start` before their
document or part workflow. DockerSW manages startup through its entrypoint.

`swcli/v1` remains pre-stable. Request replay is bounded, daemon-local and
non-persistent. Reusing a request ID returns the first terminal result, including
failure; use a new ID to attempt the operation again. Transport authentication,
general sketch/feature operations, stable entity references, transactions, SDK
and MCP remain future work. Remote endpoints must use a trusted boundary or an
authenticated tunnel.
