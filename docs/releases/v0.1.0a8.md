# SWCLI v0.1.0a8 — release draft

**Not published.** The checkout reports `0.1.0a8.dev0`; the current published
wheel is v0.1.0a7. This draft does not announce release assets or a completed
formal-version Windows/DockerSW delivery gate. Installation commands and exact formal-candidate
receipts must be added before publication.

## Changes since v0.1.0a7

- Read-only `entity.list/inspect` observes exact faces (default) or explicit
  edges (`--kind edge`) of one complete solid part. Short `e-` IDs are registered
  only after native persistent-reference round trips, exact ownership/identity
  checks, complete enumeration and unchanged document/application state.
- Face output includes approximate native area and available analytic plane or
  cylinder geometry in explicit part-model units. Edge output separates raw
  native start/end/U/Sense/type parameters from untrimmed line or circle
  geometry. Other analytic geometry is explicitly unavailable, not guessed.
- Faces and edges share one conservative configuration/update-stamp scope.
  Same-scope reads reuse exact IDs and preserve the other kind's handles. An
  observed scope change permanently retires both kinds, including when a later
  geometry check fails. Close/reopen issues fresh IDs. Rediscovery is explicit;
  stale references never silently become the nearest geometrically similar face.
- Stopping an explicitly attached daemon now detaches normally even with user
  documents open. The user's SOLIDWORKS remains running and is never closed or
  force-terminated. Daemon-owned hosts still require documents to be closed
  before an orderly stop. Shared-host timeout/disconnection recovery policies
  are unchanged; this does not grant safe continuation after an unknown COM state.
- The shared modeling gate checks both kinds on the existing depth fixture,
  including mixed-ID reuse, wrong-kind/CAS/cross-document refusal, actual depth
  writes and native save/read-only reopen. Windows runtime CI now installs the
  wheel built in that same workflow instead of an editable source checkout.
- A shared Toolbox gate checks registry-discovered deployment inventory and a
  representative native part through read-only open/diagnose/measure/close on
  the existing host. Windows cold installation explicitly selects the official
  Toolbox feature chain. Its mount prerequisite uses the official pinned,
  SHA-256-verified WinFsp MSI rather than trusting a Chocolatey summary alone.

## Read-only example

On a matching development daemon advertising the entity operations, after
opening or creating a supported part:

```powershell
sw-cli entity list --document DOCUMENT_ID --json
sw-cli entity inspect FACE_ID --document DOCUMENT_ID --json
sw-cli entity list --kind edge --document DOCUMENT_ID --json
sw-cli entity inspect EDGE_ID --kind edge --document DOCUMENT_ID --json
```

Replace the placeholders with returned exact document/entity IDs. An opaque ID
does not select its kind: inspecting an edge requires `--kind edge` too. Both
operations accept session/document and an optional expected update stamp, not
a lease token; observation does not acquire write authority or change session
current. Check capabilities rather than assuming an a7 daemon implements these
development commands.

## Supported scope and limits

- One complete solid part, no surface bodies or multiple solids, and 1–64
  entities of the requested kind. Limits are complete-read bounds, not paging:
  exceeding a bound fails instead of silently returning a partial list.
- Reads stay on the owning STA without activation, selection, rebuild or save.
  Foreground, edit identity, configuration, modified flag and update stamp are
  checked before/after. A lease does not exclude GUI edits or other daemons.
- Analytic geometry is not a trimmed boundary or identity key. No edge length,
  closure, seam, adjacency, owning feature, normalized trim, fillet/chamfer target
  editing or arbitrary topology-edit survival is promised.
- `EntityReferenceStale` requires rediscovery and reconsidering the target;
  `EntityNotFound` covers unknown/cross-document/closed handles. Native persistent
  reference bytes stay private. IDs are not durable cross-worker CAD references.
- Toolbox inventory and a representative read-only part are not proof of every
  standard, specification selection, generated configurations or insertion into
  an assembly. Deployment remains the host project's responsibility.

Request replay remains bounded, process-local, best-effort and nonpersistent.
Reusing a request ID returns the first terminal result **including failure**;
a new attempt needs a new ID. Daemon restart clears the cache. This is not a
transaction journal or an automatic rollback guarantee. SDK/MCP, transactional
batches, authenticated remote transfer and OpenSCAD conversion remain roadmap
items, not a8 capabilities.
