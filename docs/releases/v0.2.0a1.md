# SWCLI 0.2.0a1

- `swcli mcp serve` provides a stdio MCP adapter over the existing `swclid`
  protocol. Lifecycle tools explicitly start, inspect and stop the selected
  host through native Windows or a configured daemon utility. Discovery does
  not start SOLIDWORKS, and closing the MCP stream keeps the daemon alive.
- The client exposes runtime/host observations and packaged skills with the
  official API references. CAD operations retain document, session, lease and
  update-stamp guards. The daemon's capabilities define the actual host scope.
- Includes a18 document length-display options for parts and assemblies, and
  seven annotation scalars for parts, assemblies and drawings. Font settings,
  overall drafting-standard edits and the rest of the document-options dialog
  remain separate work.
- CI retains original output and adds a common JSON/Markdown summary, with
  business failures and cleanup failures separated. The Windows lifecycle gate
  now records task/process inventories around startup and shutdown boundaries.

The combined Windows candidate passed the complete installed CLI gate in
[42199134982](https://github.com/YJBeetle/SWCLI/actions/runs/42199134982).
Its original wheel/sdist, native geometry and export receipts, document-option
save/reopen traces, and task/process lifecycle snapshots were independently
verified. The version-tag workflow verifies its own original artifacts before
publishing them.

Native Windows is SWCLI's primary runtime and release acceptance target.
DockerSW and MacSW maintain their Wine delivery and versions independently;
Wine-specific failures do not block a verified SWCLI Windows release.
