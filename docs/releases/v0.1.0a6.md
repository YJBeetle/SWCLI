# SWCLI v0.1.0a6 — draft, not published

This is the development release checklist for the rectangle size/positioning
slice. The package still reports **0.1.0a6.dev0**; the latest published release
remains [v0.1.0a5](v0.1.0a5.md). Do not use a nonexistent a6 release URL or treat
an installed development wheel as a published release.

## Candidate changes

- `sketch fix-center SKETCH_ID` explicitly fixes the verified current native
  center of a supported unabsorbed center rectangle. An exact existing fix is
  a verified no-op. Extra/suppressed/origin relations are refused; coordinates
  alone do not prove the presence of an origin relation.
- `sketch dimension-rectangle SKETCH_ID --width-mm W --height-mm H` creates
  verified native width/height driving dimensions. It **does not fix the center
  implicitly**. Each solver step must preserve placement; a failure may leave
  partial native dimensions and retains that evidence without publishing an
  unverified pair of public IDs.
- `dimension inspect/set` also support registered rectangle width/height IDs.
  Inspection is read-only and reports external controls. Edits preserve the
  other axis and center, affect only the current configuration and check native
  readback, complete rebuild diagnostics and applicable downstream body metrics.
  Driven/read-only/equation/design-table controls are not overridden.
- `dimension discover-rectangle SKETCH_ID` recovers one observable exact native
  width/height pair, including absorbed profiles after native save/reopen. Both
  dimensions and independent geometry must agree with unchanged configuration,
  stamp and edit state. Partial, ambiguous or unavailable reads publish no IDs.
  The command does not activate the document, select entities or force dimension
  display preferences. An empty display chain is not proof of absent dimensions.
- All operations retain the daemon-only protocol, document/session selection,
  typed request/result contracts and appropriate lease/stamp guards. Reads may
  observe another session's leased document; a discovered handle does not grant
  modification authority. Front-plane shared gates use installed CLI commands
  with the document selector before positional handles.

## Development example

This needs a matching development daemon advertising these operations; the a5
wheel cannot run it. The explicit positioning command is intentionally separate
from the two size dimensions:

```powershell
sw-cli document create --json
$sketch = sw-cli sketch rectangle --plane front --width-mm 40 --height-mm 30 --center-x-mm 3 --center-y-mm 4 --json | ConvertFrom-Json
sw-cli sketch fix-center $sketch.sketch.sketch_id --json
$size = sw-cli sketch dimension-rectangle $sketch.sketch.sketch_id --width-mm 40 --height-mm 30 --json | ConvertFrom-Json
sw-cli feature extrude $sketch.sketch.sketch_id --depth-mm 10 --json
sw-cli dimension set $size.dimensions.width.dimension_id --value-mm 50 --json
sw-cli dimension set $size.dimensions.height.dimension_id --value-mm 35 --json
sw-cli document measure --json
```

After closing/reopening a saved native copy, obtain a fresh sketch via
`sketch list`, then call `dimension discover-rectangle` with its returned ID.
Never reuse the expired document/sketch/dimension handles or guess native names.

## Boundaries

Only exact axis-aligned rectangle profiles and an observable unambiguous native
axis pair are supported. This is not arbitrary linear dimension/constraint
editing, a complete constraint solver, multi-configuration editing or automatic
transaction rollback. Center fixing has narrower profile/relation prerequisites
than width/height observation. Saved center relations are native evidence, not
persistent public constraint IDs.

Handles and leases remain worker/document-local. Request replay remains bounded,
daemon-local, in-memory and best-effort: the same request ID returns the first
terminal result **including failure**; a new attempt needs a new ID. Daemon restart
clears replay memory. Leases/stamps do not lock human GUI edits or other daemon
instances. Explicit host disconnect/recovery behavior is unchanged.

The MacSW intermittent close/software-renderer issue remains a separate host
investigation. A passing local Windows run or a later green MacSW run does not
establish that issue's root cause or permanent resolution. SDK/MCP, stable
topology references, transaction batches, remote transfer/authentication and
OpenSCAD conversion remain separate roadmap items.
