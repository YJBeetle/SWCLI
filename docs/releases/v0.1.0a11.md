```bash
sw-cli document create --type drawing --template A4.DRWDOT --projection third-angle --json
sw-cli drawing standard-views SOURCE_DOCUMENT_ID --configuration CONFIGURATION --document DRAWING_ID --json
```

The first creation slice uses calibrated A4 paper, an explicit existing DRWDOT
and explicit first/third-angle projection. It does not promise arbitrary paper
inheritance or generate templates. A missing legacy external format path is
reported, never silently replaced. Embedded title-block fidelity is not proved
by that warning or by export file validation.

Standard views require an empty single-sheet writable drawing and an already
open, saved, clean, rebuilt PRT/ASM in the explicitly named active configuration.
It never switches or saves the source configuration. Target lease/CAS and
cross-document guards run before activation; a source leased by another session
is refused. Temporary activation restores the previous foreground without
changing session current. Sheet/view positions and outlines use meters.

Exactly three model views must agree with native source/configuration,
calibrated standard-frame matrices, scale and nonoverlapping paper layout.
Custom model view frames may be refused; no automatic dimensions, BOM, arbitrary
layout, section views or multiple-sheet editing are included. Partial insertion
retains mutation/view/error evidence; no automatic retry, deletion or rollback.

## Shared gate integration

The full runtime plan adds a separate owned-host `drawings` set; the core plan
and six delivery exports are unchanged. It composes only public CLI operations
for first-angle PRT and third-angle generated ASM drawings, lease/CAS refusals,
background identity, native save/reopen, public structure/diagnostics and strict
PDF/DWG exports. Reopened view transforms/references are not publicly exposed
by document inspection; this gate does not claim their independent readback.
The separate native calibration retains that stronger persistence evidence.

Host adapters supply the official base `data/templates/gb.drwdot` from the selected
installation, or an explicit `SWCLI_DRAWING_TEMPLATE` path. Fresh Windows CI also
lacks the workstation's generated `ProgramData/.../gb_a4.drwdot`; its first run
stopped at fixture discovery before any drawing CAD operation. Host selection
was corrected without weakening the actual A4 sheet or view checks. Missing or
ambiguous fixtures fail rather than selecting an arbitrary template.
Portable full suite passed 1416 tests (20 platform skips) during integration;
wheel/sdist verification and isolated installed resources passed. These are
not fresh native CI receipts. The agent guide now includes the drawing workflow
and does not advertise it as part of published a10.

The first real Linux/Wine drawing set found a fixture-lifetime assumption: closing
the drawing also unloaded its background source; reopening loaded that source
under a new ID. The registry correctly expired the old handle. The gate now checks
the original source before close and explicitly reacquires saved model paths for
the post-reopen full structure/clean-state/hash checks. Both PRT and ASM cases
passed in one owned instance on workspaceroot, without retries or host restart.
See [the focused record](../verification/drawing-linux-wine-2026-10-24.md).

Windows CI `39993646756` subsequently stopped before CAD tests because Windows
PowerShell 5 passed a registry installation directory with spaces and a trailing
backslash as a native argument with a stray quote. The wrapper trims only trailing
directory separators before calling the fixture resolver. A Windows-only test
executes the actual production PowerShell call against a temporary space-bearing
installation to catch this in the fast unit job. Revalidation at `2c5c100`
passed in [Windows CI 39998974266](https://github.com/YJBeetle/SWCLI/actions/runs/39998974266),
and subsequent Windows full-plan runs also pass. This resolved fixture argument
passing, not the independent MacSW native timeout.

## Known Mac CI limitation and release gates

- The hosted Mac CI has only software rendering (owner-confirmed). Its complex
  official drawing's second OpenDoc6 exceeds the retained 600-second budget;
  native stacks include drawing graphics/OpenGL calls. This is not proof of a
  deadlock, nor a completed full Mac acceptance run. On 2026-10-25 the owner
  explicitly accepted it as a known **non-blocking a11 CI limitation**, because
  Windows and DockerSW already validate the shared CLI/CAD/Wine functional
  chain. Mac integration/lightweight smoke remains separate evidence. Do not
  suppress the timeout or promise that every Mac/hardware path is validated.
- Freeze matching host pins only at the final verified candidate, then verify
  installation and hashes using that candidate's original CI wheel/sdist.
- Publish exact receipt/asset provenance and the a11 tag only after the above.

The added native COM/backtrace entrypoints are CI-only diagnostics. They are
not public raw-COM APIs and cannot replace the normal 19-set runtime gate.
