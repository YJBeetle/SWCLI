# SWCLI v0.1.0a4 — release candidate notes (unpublished)

This is a draft for the next pre-release, not a published tag or download URL.
The current development package is `0.1.0a4.dev0`; the published wheel remains
`v0.1.0a3` until the release is explicitly made.

## Installation while developing

From a checkout of the intended verified commit:

```powershell
python -m pip install .
sw-cli version --json
sw-cli doctor --json
sw-cli daemon start --visible --json
```

Windows automatically installs pywin32; no `[windows]` extra is needed.
Linux/macOS clients use `python3 -m pip install .` and connect to an explicitly
running daemon. Their local files are not uploaded to a remote execution host.
Stop an old daemon before upgrading and explicitly start the matching version.
For a locally built wheel, install that actual wheel rather than relying on a
source-path override. Final release notes must provide the pinned public wheel
URL only after the corresponding asset exists.

## Changes since v0.1.0a3

- One operation catalog now owns request parameters, output contracts,
  document selection, lease guards, activation policy and worker handlers.
  Runtime adapter result validation rejects mismatched/false-success payloads.
- `document create` creates an unsaved part with an exact live document handle.
- `sketch rectangle` and `sketch circle` create verified, closed 2D sketches on
  front/top/right origin planes using explicit sketch-local millimeters and
  short document/worker-scoped IDs, not translated names or an active sketch.
- `feature extrude` builds a blind solid boss with reverse/merge control;
  `feature cut-extrude` removes material at explicit blind depth. Both validate
  native definitions and rebuild diagnosis. Cuts use explicit all-solid scope
  and require measured material removal. The CLI direction is along the sketch
  normal by default for both bosses/cuts; `--reverse` is against it.
- `sketch inspect` re-observes live registered profiles, including absorbed
  ones, without activation/editing. It reports native constraint/owner state
  and local line/arc geometry, explicitly warning about other undecoded types.
- `document measure` reads kernel-derived solid volume, area and volume-weighted
  centroid without changing the model. It sums bodies rather than unioning
  overlap/contact regions and does not imply real material mass.
- `document save-as` gives a part a new native filename without overwriting an
  existing target, preserves live document/lease/sketch handles, and reports
  native save/path/state/file-size evidence. Close/reopen verification remains
  necessary; the size check is not a proprietary-file integrity validator.
- A portable product skill/agent guide ships in the wheel. The source archive
  includes both READMEs, design/roadmap/release docs, verification scripts and
  the executable four-hole plate example. CI checks actual installed resources
  and source archive completeness rather than only testing a checkout.

## Evidence required before publishing

Record the exact release commit and Windows/Wine CI links, not just a version
string. Require portable tests, Python 3.9/3.14 and installed-wheel/source checks,
native Windows modeling/save/reopen/export/failure/lifecycle gates, and DockerSW
Wine modeling/observation gates plus its six real export artifacts and image
promotion. A green native Windows run does not prove Wine delivery, and a built
wheel does not prove the installed product. Validate the public plate example's
strict STEP export and analytic volume/area after native reopening.

## Boundaries and compatibility

This remains a pre-release: `swcli/v1` has no stable compatibility commitment.
Use matching client/daemon capabilities, not a hard-coded README operation list.

Sketches are native/editable but do not yet create driving dimensions or promise
full definition. Only blind one-direction bosses/cuts are covered, not
through-all, draft, thin features, chosen-body scope or arbitrary face references.
Success verifies declared native/geometry evidence, not the whole engineering
design. Observational names/indices are not stable entity handles. Document and
sketch IDs expire on close/worker restart; save-as keeps them only while live.

Failed operations can leave a partial model or an adopted save-as filename.
Inspect and diagnose before retrying; there is no automatic transaction/rollback
guarantee. Export/render use verified temporary outputs before replacing their
formal destination, while native naming/save-as has a different state boundary.

Request replay remains bounded, daemon-local, in-memory and best-effort. Reusing
the same ID returns its first terminal result **including failure**; an actual
new attempt needs a new ID. Daemon restart loses this cache. Leases/stamps guard
cooperating clients, not GUI edits, separate daemons or distributed filesystems.

Authenticated remote transport/file transfer, stable topology references,
transactions, typed SDK/MCP, dimension-driven editing and assembly/drawing
creation remain later work. The OpenSCAD goal is editable native feature trees,
not mesh-only import; this release does not implement a converter.
