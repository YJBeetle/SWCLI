# SWCLI 0.2.1

- MCP exposes five tools: `status`, `daemon_start`, `daemon_stop`,
  `capabilities` and `execute`. The server remains `swcli`; CAD operations and
  document/session/lease/update-stamp guards stay unchanged. Packaged skills
  and the MCP guide use these tool names.
- Windows daemon startup supports `--tray auto|on|off`; MCP `daemon_start`
  accepts the same `tray` option. The default shows a notification icon on
  native Windows and keeps it off under Wine, independently of SW window
  visibility. Reusing a running daemon leaves its settings unchanged.
- Background Windows startup uses the same installation's `pythonw.exe`, so
  the resident daemon and COM worker do not open a console window. Daemon
  output continues to go to the startup log.
- The notification icon uses MacSW's purple cube artwork, packaged at native
  Windows icon sizes.
- Right-click the icon for runtime status, confirmed daemon stop and hide-icon.
  Status opens only after selecting **查看状态**; left-click has no action.
  Hiding the icon keeps daemon/SW running. Stop uses the existing protocol
  and open-document/attached-user-host protections. Normal shutdown removes
  the icon. In auto mode an unavailable notification area records a
  diagnostic; explicit on reports `TrayUnavailable` before starting SW.

Windows desktop checks covered native icon registration/removal and actual
MCP attachment, stream disconnect, status display, icon hiding and normal
shutdown while preserving the existing user SW. See
[the desktop verification scope](../verification/0.2.1-windows-tray-2026-11-06.md).
The version-tag workflow runs the complete installed Windows gate and publishes
its original wheel/sdist only after success. DockerSW/MacSW integration and
independent multi-instance support remain separate work.
