# SWCLI v0.1.0a7

This pre-release adds exact part-extrusion feature handles, read-only native
definition observation and guarded depth editing. It does not promise general
feature editing, arbitrary profiles or a stable `0.1.0` protocol.

## Installation

Stop an old daemon before upgrading; document/sketch/dimension/feature handles
and leases expire on restart. Release assets include the wheel, source
distribution and `SHA256SUMS`.

Windows (pywin32 is installed automatically):

```powershell
sw-cli daemon stop --json
python -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a7/swcli-0.1.0a7-py3-none-any.whl"
sw-cli version --json
sw-cli doctor --json
sw-cli daemon start --visible --json
```

Portable Linux/macOS client:

```bash
python3 -m pip install --upgrade "swcli @ https://github.com/YJBeetle/SWCLI/releases/download/v0.1.0a7/swcli-0.1.0a7-py3-none-any.whl"
sw-cli --endpoint HOST:18495 capabilities --json
```

Python 3.9 or newer is required. Portable clients do not provision SOLIDWORKS or
upload local files. Host paths are not client paths. Keep the unauthenticated
transport behind a trusted boundary or authenticated tunnel. DockerSW/MacSW
own their bundled source pins and installation; do not install a second copy
into their managed hosts.

## Changes since v0.1.0a6

- Supported boss/cut creation returns an exact `.feature.feature_id`, not a
  subsequent active/last feature. Read-only `feature.list` discovers exact live
  part-extrusion handles after open/reopen; `feature.inspect` reports native
  definition and state without activation, selection access, rollback or rebuild.
- `feature.set-depth` edits the selected exact feature through the same daemon,
  session/document, lease and update-stamp guards. It verifies native current-
  configuration scope, depth, unchanged non-depth parameters/profile/body scope,
  selection access/release restoration, complete rebuild health and independent
  body metrics. It restores the previous foreground without changing session
  current. It never saves, retries the setter, restarts the host or claims rollback.
- Equal-depth requests still verify native scope access/release but skip setter,
  configuration setter, commit and rebuild. They may advance the update stamp
  while depth/geometry and the modified flag stay unchanged. Refresh the stamp
  before another write; `depth_changed: false` does not mean a pure read.
- Failures retain typed `mutation` and `selection_checks` evidence. Staging or
  commit can leave partial state; `depth_changed: null` is an unverified outcome.
  Inspect before another mutation rather than blindly retrying or saving.
- The packaged AI skill/guide includes feature identity, editing prerequisites,
  equal-depth stamp behavior and partial-failure handling. Capabilities/result
  schemas remain authoritative; do not infer support from a newer README.
- The shared modeling gate adds background boss/cut depth edits, independent
  expected volumes, no-op checks, native save/reopen and read-only rejection.
  Independent kernel reads use explicit per-metric tolerances rather than exact
  floating-point dictionary equality. A separate 600-second depth-request budget
  does not extend other request budgets or permit retries/restarts. DockerSW's
  six export outputs and promotion requirements are unchanged.

## Minimal depth-editing loop

On a matching daemon advertising the a7 operations:

```powershell
sw-cli document create --json
$profile = sw-cli sketch rectangle --plane front --width-mm 100 --height-mm 50 --json | ConvertFrom-Json
$boss = sw-cli feature extrude $profile.sketch.sketch_id --depth-mm 20 --json | ConvertFrom-Json
sw-cli feature inspect $boss.feature.feature_id --json
sw-cli --request-timeout 600 feature set-depth $boss.feature.feature_id --depth-mm 25 --json
sw-cli document measure --json
```

Use an explicit document, session, lease and freshly observed stamp for
cooperating writers. Decide saving from task authority; in-memory success is not
persistence proof. After native close/reopen, discover fresh feature handles and
inspect depths/geometry; never recover by guessing a localized feature name.

## Supported scope and limits

The first setter requires a writable single-configuration part with one final
non-sheet-metal solid, an exact absorbed full circle or axis-aligned rectangle,
and a simple one-direction solid blind boss/cut. It refuses equations/design
tables, existing edits/commands, suppressed/frozen/rolled-back features,
thin/draft/nonblind/reference-start definitions, explicit direction/contour
references and unsupported body scopes. A readable depth is not edit authority.
Native forward depth is not material thickness or through-all travel; a cut's
native direction flag is not the creation CLI's normalized `--reverse` flag.

These guards do not promise arbitrary topology preservation or proportional
volume changes for downstream features. Real read-only refusal is covered;
other protected-control/scope negatives also have portable tests, not a claim of
exhaustive native fixture proof across all host versions.

Feature IDs remain worker/document-local, not persistent topology references.
Leases do not lock human GUI edits, other daemons or shared filesystem paths.
Request replay stays bounded, in-memory and best-effort: reusing a request ID
returns the first terminal result **including failure**; a new attempt needs a
new ID. Daemon restart clears replay memory; it is not a transaction journal.
SDK/MCP, stable entity references, transactional batches, remote transfer/auth
and OpenSCAD conversion remain separate roadmap items.
